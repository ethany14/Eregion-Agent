# R1→R2 门槛调整与 API 优先 B6 验收

日期：2026-10-12。依据：用户在讨论旧浏览器 B6 不应阻挡新来源迁移后明确确认“是的，这样没错”。本修订只调整阶段依赖，不将任何失败结果改写为通过，不增加收费额度，也不自动开启来源。

## 当前结论

**迁移准备门允许进入 R2；业务验收仍未通过。** 基于已记录的冻结版本、完整离线回归、恢复/浏览器/MCP 边界和修复后定向验证，旧 browser-first B6 失败不再作为 R2 前置阻塞。R2 启动时仍需核对工作区是否发生后续代码变化；变化影响的检查必须补做。

旧 L4 保持 FAILED（只保存一条合格推荐，原完整交付计数 0）；旧 L1 受冻结源覆盖限制失败；L3 full 失败及测试绑定修复后的真实验证待办保留。所有原始日志、账本、unknown 预留和资格断言不改。

## 两个独立门槛

| 门槛 | 要求 | 时间 |
|---|---|---|
| 迁移准备门 | 可重建基线、离线正确性、预算/取消/恢复/所有权保护、明确采用决定和问题归属、完整账目 | R1→R2；旧来源覆盖失败不阻挡 |
| 最终业务门 | 至少两条符合岗位/资历/地点要求的有效岗位；完整 JD、资格核验、正式评分、明确推荐、持久化、最终回复链接和分数；预算受控 | API 优先迁移配置上，R6 首次验证，R8 配置冻结后在 R9 确认 |

如果 R6 的验证配置、代码和来源与 R8 最终配置一致，R9 直接引用已有证据；有实质变化只补受影响验收，不无理由重跑收费测试。任一最终采用配置未过业务门，不得宣称全链路完成或默认发布。迁移途中出现新的正确性、越权、重复执行/计费、取消或恢复缺陷仍然阻塞当前阶段。

## 执行顺序

1. R2/M1：核对冻结基线与后续改动，补统一执行/模型契约、非法响应保护、计量边界、API-first 提示一致性和 Treg 客户端关闭；做离线回归。
2. R3–R5：按原统一 Loop 计划收敛 Session、固定工作流、调度与资源生命周期，逐阶段验证。保留材料 full 的 grounding 问题，由 R3 材料工作流任务接手；patch 默认关闭，full 真实验收不得被浏览器门调整豁免，需在材料迁移验收/最终交付前完成。
3. R6：在新执行体系接通已实现的招聘板 API＋用户自配 Treg，先契约/离线来源链路回归，再做有界 API 优先 B6。不重复开发已有接入，不重开旧 Treg A/B。
4. R7：LinkedIn MCP 按原计划离线→真实只读→必要对比。只有验证可用后才参与来源策略；未装/未登录/未通过不阻挡招聘板＋Treg 主线。
5. R8–R9：冻结通过的来源策略，确认对应 B6 业务证据；保留无额外凭据的基础路径、开源配置与失败提示。

## API 优先 B6 的任务与路线

使用原合成候选人、纽约 junior Data Analyst 目标和至少两条合格推荐标准。仅将用户任务中的“Start with LinkedIn or Indeed”替换为“优先使用已配置且通过契约验证的招聘板 API／Treg 获取候选；缺 JD 或有证据冲突时补读页面；必要时浏览器核验”。不得同时要求 prompt、snapshot、工具描述走 browser-first。Treg 只提供候选不等于岗位已合格。

公司/board 发现→按可用来源检索→跨来源去重→补完整 JD→岗位资格核验→正式评分→明确推荐/排除→持久化→用户交付。来源选择依据配置、健康、覆盖和预算，不要求每次遍历全部来源。MCP 只有验收通过且已配置时可参与，不能把潜在能力算作已接入。

浏览器补充能力保留离线与必要本地验证：缺正文补读、来源冲突、来源不可用时返回明确状态、取消/恢复/会话所有权。无需证明自主浏览器独立找到两条岗位才能迁移；登录挑战或限流不允许同账号换通道绕行。

## 测试与账目要求

新增来源策略参数或独立测试节点，保留原 browser-first 节点和失败原件，复用原 evaluate_search 业务断言。原验收的 60 主调用、主/总各 1M 输入上限保留；沿用当前运行器更严格的 60 总 provider attempts，不能静默提高。Treg 外部工具费用单独记账，调用前检查用户配置、原批次剩余额度与任务/日/单次限制。

新样本必须记录新编号、确切代码版本、有效 flags、来源/模型设置、每次 attempt/失败/unknown、model 与 external-tool 分账。旧 29,997 输入预留继续保留。此次门槛调整不是新收费批次授权；既有明确授权继续有效，超出范围或额度才补授权。L1 冻结归档仅作有限历史回归，不要求花钱修成全网模拟器；没有可比成功基线就不报告百分比加速。

## 文档优先级与交接

本修订覆盖旧计划中“必须先通过 browser-first L4 才允许 R2”的阶段依赖；其余权限、预算、资格、恢复与材料质量要求保持。R1 状态拆为“迁移准备门已放行 / 业务门待迁移后验收”，不能简写成 optimization 全部 PASS。
