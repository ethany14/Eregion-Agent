# Eregion 成本与时延优化方案 v3（2026-10-11）

取代 `optimization-plan-v2.md`。本版吸收 Astra 对 v2 的五点审查，并修正 v2 中的错误数字和 B6 描述。v2 保留作历史记录。

原则：
- 先量后改，基线必须代表整段任务；
- 验收看业务结果（完成率、资格正确性、整项任务费用和耗时），不看测试数量或单一指标；
- 每项优化一个开关，可回滚；
- 稳定性不等于准确性。

## 3. 路线

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| 0 校准现状 | 审查阶段 0–1（已完成）；修正方案数字；修复兼容重试的默认行为；计量补上持久窗口裁剪；预算覆盖所有 provider attempt | 基线、代码版本、配置和失败证据一致；关闭新开关时请求逐字节不变 |
| 1 预算与来源推进 | 调用、输入和重试预算按 provider attempt 预留和扣减（含嵌套与重试）；建设可信公司招聘板目录（按真实用户搜索范围维护，记录来源、更新时间和覆盖缺口）；HTTP 连接复用；来源健康管理 | 失败成本可归因；换 query、工具、参数或重启都绕不过保护；有健康候选时能继续推进；新来源保留资格证据、去重和无进展治理 |
| 2 低风险请求优化 | snapshot 去重、正文改为引用；稳定、精简的工具组；固定提示去冗余；**同时设计**持久窗口与请求层裁剪及检查点，比较多种策略 | 整项任务输入下降；必要事实和当前任务能力仍可达；B6 回放业务结果不变 |
| 3 按用途推理实验 | 先做 router 和 writer；面试保留已验证的 `low`；评分和 verifier 用更严格的质量门（见第 4 节） | 计入失败和重试后，总费用或耗时下降，质量不退化 |
| 4 减少机械往返 | 把 read/import/score 等明确步骤封装为可恢复的工作流，保留逐步校验和幂等 | 模型调用减少，业务验收结果保持（资格、评分、落库、最终陈述正确）；不要求工具轨迹相同 |
| 5 条件式 RAG | 只在精确取回仍导致反复翻页、找不到历史证据或上下文持续超限时才做：FTS5 + 元数据过滤 | 证据召回可靠，未命中有回退，检索开销计入总成本 |

阶段 1（来源）和阶段 2（上下文）互不依赖，可以交替推进。同一工作区一次只跑一个 Codex 任务。

## 4. 质量与验收门

- **业务结果**：
  - B6：合格推荐数（按不变的 `evaluate_search`）、资格证据、披露阻断、不冒充完成；
  - 材料：grounding 加人工风格审阅；
  - 面试：问题绑定、恰好一次、延迟。
- **整项任务费用**：每个场景的 input、output、reasoning、cached 和重试，包含失败运行的成本。命中率只作诊断。
- **回归**：固定 commit 和测试集合；无新增失败；每个跳过项写明原因。
- **评分**：降推理量或换模型需要 A3 人工标签作为标准答案。A1 一致性只证明稳定，不证明准确（"稳定地漏掉 Python/SQL"就是反例）。
- **verifier**：降推理量必须通过一组正反例：
  - 错误事实被放过；
  - 正确事实被拒绝；
  - 跨申请人证据混用；
  - 修饰词夸大（例如 "built" 被写成 "led and scaled"）；
  - 只看 E5 自动检查不够。
- **真实运行**：先用离线回放把关；真实结果的样本量要写明，小样本（如 3 次）只作初步观察。代表性的真实基线需要一次带新计量的真实运行（付费，需用户批准）。
- **提示缓存**：缓存键不保证命中，OpenAI 兼容接口是否支持需要单独做付费验证；默认关闭。

## 5. 不做 / 暂缓

模型工具搜索（先优化现有筛选）、默认摘要压缩、子智能体、推测执行、多模型抢答、训练推理量路由器。语义答案缓存只限通用知识。
