## 4. S2 正常权限环境离线复验

先从 validation.json 精确提取 13 个异常节点：4 个 Chrome setup errors、4 个 browser-recovery failures、5 个 MCP subprocess failures。在能够正常启动本地浏览器/命名管道的环境重跑这些节点，不更改断言或生产错误处理来掩盖环境失败。

离线运行要求：

- 清除测试进程中的 live opt-in，保留 `tests/conftest.py` 网络隔离。不能为修命名管道权限而开启收费调用或真实网站访问。
- 使用独立测试库和新输出目录，不碰用户数据库。优先正常权限下 ordinary pytest；已有 `scripts/pytest_workspace.py` 仅用于临时目录 ACL 兼容，不替代业务断言。
- 环境可用后，在 S1 的最终版本跑一次完整离线套件；最终修复后的相关定向回归必须通过。测试数量允许随真实新增用例变化，按节点/语义比较，不机械要求旧计数。
- skip 逐项分类；live opt-in、浏览器 opt-in、平台限制分开。普通全量默认跳过的关键浏览器测试不等于验收过，至少明确覆盖与迁移直接相关的恢复、所有权、取消、确认/收据边界。
- 若同环境旧基线也失败，保留复现证据并修复环境；若是实现回归，停止后续收费测试，定位并做最小修复，更新版本后重跑相关检查。不得以“旧版也失败”替代放行证据。

产物：`docs/diagnostics/r1-offline-revalidation-20261012.md` 与新运行目录，包含命令、版本、节点结果、skip 原因、原始日志和变更前后比较。

| 1 | L1：真实 router＋冻结网页，B0/B4 交替，计划各 3 个样本 | 每次 ≤400K 输入、≤60 attempts；L1 累计 ≤2.5M 输入，包含历史尝试与保守 unknown 预留；沿用 replay timeout | 判断阶段 4 采用；模拟评分不得声称真实评分质量已通过 |
