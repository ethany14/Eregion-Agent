## 4. C1：先修决策推进

### C1.1 评分后的待决策状态

复用 `scored_not_recommended` 与现有持久状态，使当前用户 revision 下每条已评分候选都有可追踪的处置：

- 待决策：当前岗位身份、评分和资格证据可用，尚未形成结论。
- 已推荐：经过原 `recommend_job` 校验并持久保存。
- 已排除：明确的用户条件/资格证据或合理匹配判断及理由，不能只有“继续搜索”。低技能匹配分本身不是未满足硬条件的证明，不新增隐含分数门槛。
- 待补证据：列缺少什么、可用读取路径，以及被阻断时的原因；未知不能自动变成符合或不符合。

具体字段按现有领域模型实现，不强制新增表。决策绑定岗位 identity、JD/简历或评分版本和用户目标 revision；新证据、评分失效、用户条件改变时重新验证，不能沿用不兼容的旧结论。重启不丢待决策项，同一岗位不重复推荐。

### C1.2 当前决策所需信息直接可见

审查从工作流结果、归档摘要、snapshot、历史裁剪到最终模型请求的整个链路。当前待决策岗位保留有界的：身份/URL、实际分数或区间、资格状态与关键原文引用、缺口、完成/失败步骤、下一步允许动作。完整 JD 和长评分报告仍按引用取回，禁止为了减少读取把所有全文重新塞回每轮请求。

字段不足时只取决策需要的字段或范围；不得按查询参数伪造岗位地点/年限等证据。证据不能只存在于暂存 client 内存，重启和裁剪后仍可验证。

### C1.3 推进与最终交付

- 优先处理有证据可决策的已评分岗位，再为真实缺口继续搜索。不能无限用新 query 回避待决策项。
- 未解决项可以明确保留待核验，但必须指出缺口，不能强行推荐或删除以凑验收。
- 来源不足时保留已取得的有效推荐，明确只找到 0/1 条及剩余缺口；不宣称全网没有岗位。
- 正常结束、等待用户、预算终止、无进展终止仍保持现有真实语义。故障/取消不能改标正常完成；若 breaker 触发，通过已有终态展示机制交付已保存结果和原因，不再追加收费模型调用来美化失败。
- 最终回复与持久推荐状态一致，已评分但未推荐的结果注明理由/待核验，不伪称合格推荐。

## 5. C2：修重复读取，保持精确取回

现有重复范围推进、读取进度和 `no_new_evidence` 已经存在。先定位重复发生在引用/路径/范围、失效版本、归档套归档、证据窗口淘汰，还是模型忽略指引；只修已复现原因，不新增一套重复计数器掩盖问题。

- 在相同 ref、path、原文版本和范围已可见时，直接复用；缺失事实优先精确 path/range 取回，不从整个 JSON 第 0 字符重新翻页。
- 读取进度与“本轮实际可见的证据”分开：以前读过但当前已被淘汰、或用户明确要求复查时，仍允许受控精确重读。不能全局封禁 `read_context`、过早封禁全部读取或一律判重复。
- 原始 ref 必须稳定；运行时提示文字、时间戳和已读标记不能为同一正文生成不断变化的新 ref。path 的已读范围不能误用为另一字段范围。
- 当前版本与历史审计分离；旧页面/旧评分不能满足当前资格或推荐需求，网站文本不能成为系统指令。
- 对确实无新证据的重复读取，保留 breaker，同时返回有界的已可见证据位置、真实缺口和合法下一步。不能为躲 breaker 将重复读取计为新进展。
- 只统计实际重复/新增证据，区分首次读取、继续分页、字段读取、显式重读和错误；从完整执行事件记录全程计数，不能只根据末尾 history 数组估算。

| 预算/无进展/来源阻断 | 可解释停止并展示已有结果；不多收费、不放宽标准、不改成功状态掩盖问题 |

## 7. C4：真实模型验收入口与采用规则

本节先交付实验入口、冻结输入和预算清单，不自动消费。真实模型实验优先采用“真实决策模型 + 冻结网页/工具来源”，减少网页可达性和岗位变化的干扰；评分/校验若继续模拟，报告必须写明，不能冒称全链路真实评分通过。

实验清单须记录：固定模型/config、测试场景/配置对、每组样本数、最多总请求、美元总额和单任务额度、重试计入方式、超限/失败停止条件、执行批次 ID。先对照 B0/B4，再评估 B2，组合放最后；不默认每组多跑完整联网 B6。出现新的机制性失败先离线修复，不自动付费重试碰运气。

采用判据：

1. 业务交付与资格准确性为前置门。更快失败、漏推荐或证据丢失不算优化收益。
2. 阶段 4 优先评估能否减少整项任务机械决策；阶段 2 同时计入额外取回造成的往返。最终依据整个任务而非单次请求大小判断。
3. 所有真实 provider、嵌套评分、重试和失败均计量；缓存 input 与普通 input 分开，费用用实际账单或锁定价格计算。计费未知明确披露，不能按总 token 比例宣称省钱。
4. 样本少时只能给候选判断；未做真实模型行为验证的开关保持关闭，不以脚本通过直接启用。阶段 2/4 可分别采用、保持关闭或延期，不要求捆绑上线。
5. 不启用 router low，不在本任务采用 writer medium，不降低评分/verifier 推理量。人工标签、风格审阅和相关质量实验另列延期。

产出：`docs/diagnostics/opt-v3-closeout-validation-20261012.md`，分列机制回归、脚本回放、真实模型冻结来源实验、完整联网验收四种证据；未运行项写未运行。每个阶段/开关给出结论、依据、默认值、回滚方式与遗留风险。

## 8. C5：收尾定义及 Treg 交接门

本任务的“收尾”是可执行基线已确定，不等于所有历史 E2E 或所有实验变绿。必须同时满足：

- 本次决策、重复读取和交付缺陷已复现、处理并通过必要离线回归；仍有会丢结果、重复副作用、越预算或违反资格的未解决缺陷时，不能标为可交接。
- 阶段 2/4 四组矩阵已完成，每个开关有明确采用/关闭/延期结论。缺真实模型额度时保持相关开关关闭，允许以“优化未启用、收益未证实”明确收尾，而不是假称优化有效。
- 冻结充足候选能通过原两条合格推荐标准；不足、阻断和终止场景能诚实交付。完整联网 B6 未通过时继续记录 FAILED/未复验；仅在证据支持时将剩余问题归为来源覆盖，不把所有未知都转给 Treg。
- A3 人工标签、Writer 风格评审、评分/verifier 实验、RAG 等可以明确延期，不强行完成来解锁下一阶段。用户暂缓事项不重开。
- 确认交接 commit/相关文件哈希、实际默认开关、测试命令/结果、数据与费用口径、未决事项。正确性修复单独说明，可选优化可单独回滚；关闭开关不删除历史证据、决策或费用账本，也不承诺恢复已经淘汰的历史。

输出 `docs/diagnostics/opt-v3-closeout-handoff-20261012.md`，明确 `ready_for_treg: true/false` 和逐项理由。false 时只列真实阻断与可独立完成工作；不能因“文档已写”填 true。

只有上述交接门通过后，才启动 [Treg 任务](opt-v3-stage-1b-treg-ab.md)。后续必须沿用本次实际选定的默认组合；不能为了 Treg 偷开被延期的阶段 2/4。若阶段 4 未启用，继续使用已有粒度工具即可。

Treg 次序仍为契约确认/预算基础设施与离线门 → AnyAPI/Crawl4AI 5 组搜索对比及 5 条 JD 抓取 → 按证据选一个默认搜索源 → API 优先、浏览器补充核验。整个 API 批次 $0.10、最多 20 次请求、每次 $0.01；开源用户自配 Treg key，支持 `.env`，补 `.env.example`/README，不做统一托管计费。HarvestAPI 非必选且不在该批次；Adzuna/TheirStack 排除。
