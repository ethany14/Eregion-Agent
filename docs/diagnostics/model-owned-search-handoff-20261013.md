## 2. 本轮已落地的改动

### 2.1 搜索资格由模型输出带证据的结论

入口：`backend/eregion/domain/search_qualification.py`；持久化与验证：`backend/eregion/runtime/career/qualification.py`。

- 模型读取原始用户要求与抓取到的完整岗位文本，逐项判断 role、location、seniority、vacancy，输出 `met / unmet / unknown / not_requested`、理由和原文引用。
- 每组最多四个岗位，输入上限 48,000 字符；超长输入保留 unknown，不静默截断以便通过。模型失败也不会切回规则判断。
- 不再依靠固定 junior 标题、0–3 年/4+ 年阈值、talent-network 关键词或公司办公室地址决定合格与否。
- 地点语义在提示词中要求区分城市内部行政区与独立邻近城市；vacancy 始终是必核验项。
- 引用必须绑定原岗位/用户原文；岗位 ID 必须完整且唯一。无效引用或缺项不获得通过。
- 未变更的请求、原文和模型配置复用判断；变化时失效。模型调用计入当前执行 owner 的预算，取消或用户改意后丢弃过时结果。
- `verify_and_score_jobs` 先取得文本，再批量资格判断，只为满足条件的岗位导入/评分。单个评分和推荐入口也使用同一判断，不留下浏览器路线旁路。

### 2.2 Jev 仍负责评分；去掉语义规则覆盖

主要文件：`domain/jev_fit/core.py`、`domain/jev_fit/resolve.py`、`domain/job_extraction.py`、`domain/domain.py`、`domain/fast_match.py`、`api/services/fit_analysis_service.py`。

- 更新匹配版本与 Jev 分类版本/缓存签名；**不能把旧版评分缓存当作新版语义判断证据。**

## 12. 重要差距披露与搜索停止（2026-10-14，验收版本 v3）

### 12.1 原因定位（核对原始证据）

- **DraftKings 差距遗漏：信息未丢失。** 完整 JD → Jev 报告（j22“机器学习、回归、模型评估”为 required，状态 `unknown`，即评分器弃权）→ 决策摘要。`required_unresolved` 共 7 项，未省略；该条 112 字符，未截断；简历全文也在观察中。问题在于模型把 unknown 当成非差距，并用次要的执照待确认项代替。“构建并部署预测模型”属于职责，没有被抽成要求。
- **搜索过早结束：缺少决策所需事实，深度不由模型决定。** 唯一 LinkedIn 查询的来源报告 408 条，只取了 2 页 20 张卡片。看板目录 34/34 已搜完。LinkedIn 剩 79 次、provider 剩约 70 次。但观察中看不到“已看 20 / 共 408”与各来源产出：这些只在归档的搜索结果里。同时，不带数量的请求固定只有 1–2 页，模型无法要求更深。

### 12.2 通用修复（`6355c3f`、`a297985`）

- **共用推荐规则与摘要说明。** unknown 表示评分器未判定，需对照简历；简历未体现的必需能力写成“简历未体现”并说明影响；先写影响申请决定的差距；待确认项不能代替重要差距；职责只有在要求入职即具备时才算差距。
- **`search_coverage` 呈现停止所需事实。** 紧挨候选队列，包括：
  - 各查询来源总数、页数与已看卡片数；
  - 看板已搜/剩余；
  - 各来源产出（卡片 → 读取 → 合格 → 推荐）；
  - 剩余 provider、输入 token 与 LinkedIn 额度。
- **`search_jobs.pages`（可选 1–8）由模型选择**，不写时沿用默认值。修正：`pages` 只用于 LinkedIn，不再传给看板 API（见 12.4）。
- **停止理由与停止说明。** 有搜索的回合，`finish_task` 需一句 `stop_reason`（结构检查）。共用提示按预期价值决定继续或停止：不设数量、查询或来源门槛，预算是上限不是目标。
- **最终回复。** 已保存推荐的内联列表带类别、差距、待确认、下一步；类别标签忽略标点差异；最终格式要求写明失败的搜索或读取。
