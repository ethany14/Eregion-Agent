# Eregion end-to-end test report

**Date:** 2026-10-10 (local) · **Commit:** `95cfda9` (main, clean tree) · **Main model:** `muse-spark-1.3-contributor` · **Jev:** `jev-1.13.0`
**Tester:** Claude Code, acting as four synthetic users against real job sites, plus a local mock ATS for the account flows

---

## 1. Verdict

Eregion is strong where judgment matters. It is honest about coverage limits, it resists prompt injection and pressure to fabricate, it handles consent and sensitive questions carefully, and it never submitted an application. The account / secure-credential / takeover machinery works.

It isn't ready for unsupervised daily use. **The agent loop regularly burns its whole step budget without finishing.** This happened in 7 of 11 long tasks: searches, materials presentation, "end interview", and the scheduled job alert. **Jev-only scoring almost never produces a usable score.** **Tailored resume PDFs lose employers, titles, dates and education.** **Applications on forms without a resume upload can never reach review.**

## 2. Scope and method

### 2.1 Synthetic applicants

Generated by `personas.py` as text-selectable PDFs. All people and contacts are fictional (`*.e2e@example.com`, 555 numbers, fictional employers marked "(synthetic)").

| ID | Applicant | Profile chosen to stress |
|---|---|---|
| A | **Maya Chen**, junior data analyst, NYC, US citizen | Entry-level search, location filter, recency filter |
| B | **Daniel Okafor**, senior backend engineer, remote, green card | Seniority, salary floor, remote-only, materials, interview |
| C | **Priya Raman**, MS CS (expected May 2027), F-1 needs sponsorship | In-progress education, visa/eligibility reasoning; **ran with Jev OFF** |
| D | **Lucas Moreno**, ER nurse → UX designer, Austin, bilingual | Career changer, honesty about gaps, edge cases, account flows |

### 2.2 Environment

* Six isolated servers, each with its own SQLite DB: one per applicant (ports 8001–8004), plus two identical scoring servers for the algorithm comparison (8011 Jev on, 8012 Jev off).
* First search round ran with `JOB_AGENT_HIDDEN_BROWSER=headless`. After LinkedIn/Indeed blocked it, the servers were restarted in the product default (**offscreen** Chrome) and searches were re-run.
* **Real sites used:** LinkedIn Jobs, Indeed, RemoteYeah, Built In, company career pages (Waymo, Stripe, Reddit, Lyft, Databricks, Airbnb, Discord), the Greenhouse/Lever/Ashby public job APIs, and the Workday CXS job API (NVIDIA, Salesforce, Adobe tenants).
* **Mock ATS** (`careers.northwind-labs.example`): a stateful sign-in → create account → email verification → 3-step application site. Requests for that one host were answered in-process through Playwright interception; nothing left the machine. Used only for the credential, verification and full-form flows that can't be run on real employers with a fake identity.
* Users were simulated over the same HTTP API the web UI uses. The UI itself was exercised in the built-in browser (Chronicle, Council, Road, Forge, Lookout / Control browser, dark mode, phone width).

### 3.4 Fit scoring: Jev-only vs main model

Same 4 resumes × 16 resume/JD pairs: each applicant against 3 real JDs in their field, plus 1 deliberate mismatch. Called through `/api/quick-analysis`, cold and then repeated. JDs from the Greenhouse API in two formats: **flat** (whitespace collapsed, like copy-paste or scraped text) and **structured** (line breaks and bullets kept).

**Summary**

| Metric | Jev-only | Main model |
|---|---|---|
| Point scores, flat JDs | **0 / 16** (all `[0, 100]`; whole JD treated as 1 uncertain unit) | 16 / 16 |
| Point scores, structured JDs | **0 / 16**; median range width **74 pts**, median 9 unknown of 12 requirements | 15 / 16 (one **502 at 120.9 s** = `LLM_TIMEOUT`) |
| Cold latency (median / max) | **1.2–1.9 s / 2.5 s** | **127–144 s / 219 s** (6 concurrent) |
| Warm (cached) repeat | 0.5–0.7 s, identical | 0.5–0.7 s, identical |
| Calls per cold analysis | ≈ 4–5 Jev | ≈ 3 main (≈ 18 k input + 39 k output tokens) |
| Separates mismatches from fits | **No**: Maya × backend [10–85] overlaps her analyst fits [15–88] | **Yes**: mismatches 3.1–15.2, fits 20–72 |
| Run-to-run stability (cold, same semantics) | Changes with **trailing newlines only**: e.g. Daniel × Stripe [30–100] / [44–100] / [33–100] | **±20 pt spread** with a one-line footer change (table below) |

**In chat:** with Jev on, every job scored in the four Jev conversations ended `needs_review` with an interval (12 of 12; 11 were `[0–100]` or similar). The Road showed "Fit —" for all of them, and agents fell back to "manual analysis". In Priya's main-model chat, a single Waymo internship produced **90 extracted requirements** (41 missing, 35 needing confirmation). That's over-extraction from surrounding page text, and it pushes a plausible fit down to about 30.

**Interpretation.** Jev is about 70× faster and roughly 2× cheaper per analysis, but as integrated it **doesn't produce a decision-grade score**. Its JD segmentation (`job_units`) relies on line breaks, and most requirements stay `unknown`. The main model gives usable, discriminating scores, but slowly. Its absolute values move about ±10 points between equivalent runs, so "70+" thresholds such as alerts' `min_score` are noisy. The docs' claim that Jev "preserves uncertainty" holds; the practical result is that users and alerts get no number to act on.

### 3.7 Interview practice (Daniel)

* ✅ Start: job-specific Q1 tied to the Datastore team's stack.
* ✅ Feedback is discriminating and evidence-quoted: a good motivation answer got **3/5**, "idk, I just fix stuff" got **1/5**, a strong technical story got **3/5**. Improvement points and follow-ups were tailored.
* ⚠️ 75–256 s per answer, slow for live practice.

### 3.8 Job alerts

* ✅ Missing timezone: asked for city and timezone, and warned that the requested role doesn't fit the resume.
* ✅ Invalid timezone rejected (422). Create, list and run-now endpoints work.
* ❌ "Every **weekday** at 9 AM": `AlertConfig` has no weekday field, so it was saved as **daily** (next run Sunday 2026-10-11) while chat said "Schedule: Weekdays".

## 7. Root causes (follow-up investigation)

A separate, more detailed analysis is in [E2E_ROOT_CAUSE_ANALYSIS_2026-10-10.md](E2E_ROOT_CAUSE_ANALYSIS_2026-10-10.md). This section summarizes the confirmed causes and adds three findings that document doesn't cover (marked ★). All file:line references are to commit `95cfda9`.

### C1: the agent loops until the step budget runs out

1. **The repeat guard only warns.** `task_host.after_action` detects a repeated result but only appends a `progress_feedback` hint. The single hard exit, `wait_after_repeated_read` ([harness.py:842](agent_runtime/career/harness.py:842)), applies only while an application is running. Searches, materials, interviews and alerts have no stop except the 100-call budget ([task_loop.py:168](agent_runtime/task_loop.py:168)).
2. ★ **The warning itself defeats read tracking.** At [loop_engine.py:225-226](agent_runtime/loop_engine.py:225), `after_action()` writes the warning *into* the outcome, and only then does `archive.tool_result()` archive it. Archive refs are content hashes ([request_context.py:41](agent_runtime/request_context.py:41)), so the same job report gets a new ref each time the warning is added or removed, and `read_context` on that ref counts as unread. Maya's search archived one job under 5 refs. Reproduced with a scripted model on `95cfda9`: an inspect → read_context → read_context cycle reads identical data under 2 alternating refs and runs to the budget (30/30 calls).
3. ★ **Jev noise pushes results over the archive limit.** Results over 5,500 chars are archived and must be paged ([request_context.py:298](agent_runtime/request_context.py:298)). Maya's `inspect_job` results were about 5,760 chars, inflated by Jev "unknown requirements" that were really the EEO paragraph, benefits text and a LinkedIn footer. So each check of a job costs 3 calls.
4. **Compaction hides actionable IDs.** For example, the interview ID needed for `control_interview(end)` sat behind a ref the model read 60 times; it never called `end`.
5. **Unusable scores give the model a reason to keep looking.** Jev intervals with no point score ([harness.py:369](agent_runtime/career/harness.py:369): `recommend_job` rejects `match_score is None`) leave the model nothing to report.

Status in the uncommitted working tree: a per-request no-progress breaker (3 stalled actions) plus `no_new_evidence` on exhausted ranges now stop both scripted loops (4 and 11 calls). The ordering in item 2 is still unchanged: the warning is still written before the outcome is archived. Fixing that ordering would make the guard robust rather than dependent on range exhaustion.

### C2: the tailored resume loses employers, titles, dates and education

1. **Jev resume projection only recognizes `Title | Company | YYYY` headers.** In [projection.py:23-55](job_agent/jev_fit/projection.py:23), a job boundary needs 3+ pipe fields whose last field *fully* matches a year, year-month, Present or Current. Reproduced: `Title | Co | Mar 2021 - Present`, `Title | Co | 2021 - Present`, `Title - Co, City (dates)` and two-line headers all collapse into **one anonymous entry per section**. Only a single bare year splits correctly.
2. With Jev on, resume warmup skips the main-model extraction ([analysis_cache.py:109](agent_runtime/analysis_cache.py:109)), so this projection becomes the material evidence. The material workflow then falls back to the section name as the heading ([application_pack/workflow.py:100](agent_runtime/application_pack/workflow.py:100)).
3. The PDF hides headings equal to the section name and did not render education bullets ([pdf_rendering.py:114-148](job_agent/pdf_rendering.py:114)), so education disappeared completely.
4. Verification ([quality.py:415](job_agent/quality.py:415)) compares the draft with the already-degraded source, so it passes.

### C3: applications never reach review on forms without a resume upload

* `pending_documents()` ([autofill.py:73-78](agent_runtime/auto_apply/autofill.py:73)) returns `['resume']` whenever `document_refresh.resume` is set, without checking for a file field. That flag is set for every run, including `open_application_url` with `material_refs={}`.
* All three review gates check it: `agent.py:427`, `runner.py:196` and `loop.py:874`.
* The flag clears only after a successful upload, which can't happen without an upload field.

### C4: Jev produces no usable score

* `job_units()` ([core.py:115](job_agent/jev_fit/core.py:115)) splits only on line breaks, bullets and some headings, so a flat JD becomes one compound unit.
* Extraction needs a confident answer to both "is a requirement" and "is preferred". `boolean()` treats 0.15–0.85 as unknown.
* Uncertain extractions skip evidence matching but keep full required weight, which produces wide intervals. Uncertain condition classification also blocks a status.
* Raw text (including trailing newlines) is both the model input and the cache identity, so formatting changes alter results.
* ★ **The browser locale is unset.** `new_context()` ([browser.py:289](agent_runtime/auto_apply/browser.py:289)) sets no `locale`, so Chrome follows the OS (zh-CN here). LinkedIn served Chinese pages, and Chinese UI text such as "Show more 职位级别 助理" became a "required" requirement.

### Other confirmed causes

| Issue | Cause |
|---|---|
| Weekdays saved as daily | `AlertConfig` has no day-of-week field ([alerts.py:21](agent_runtime/career/alerts.py:21)); the agent's confirmation isn't checked against the saved config |
| Alert digest says "Send continue" | The scheduler uses the conversation's last assistant message as the digest, including budget-stop notices |
| Cross-conversation run sharing | Dedupe is by posting identity with no conversation ownership (`auto_apply/repository.py:107`, `harness.py:695`); `cancel()` cancels every linked run |
| Takeover drops after navigation | `_resume_after_handoff()` (`auto_apply/loop.py:136`) auto-resumes when the verification wall disappears, even while `paused_for_control`, so later control calls fail the pause/revision check (409) |
| Main-model score spread | Requirement sets and match judgments are model-generated (`temperature=0` already); extraction includes duties, benefits and EEO text, and `LLM_TIMEOUT` applies per request |
